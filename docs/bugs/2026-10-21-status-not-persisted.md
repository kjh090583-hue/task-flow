## BUG-1. 새로고침 뒤 카드가 "할 일" 열로 돌아간다

### 재현 순서
1. API(`cd backend` → `uv run fastapi dev app/main.py`)와 화면(`cd frontend` → `npm run dev`)을 켠다.
2. 브라우저에서 http://localhost:5173 을 연다. "할 일" 열에 카드가 하나 이상 있게 한다 (없으면 제목 "장보기" 를 입력하고 "저장" 을 누른다).
3. "할 일" 열의 "장보기" 카드에서 상태 드롭다운을 열어 "진행 중" 을 고른다.
4. 카드가 "진행 중" 열로 옮겨 간 것을 확인한다. (캡처 1)
5. F5 를 눌러 새로고침한다.
6. 카드가 어느 열에 있는지 확인한다. (캡처 2)

> 이 순서는 직접 확인한 검수자가 쓴 것이다. 같은 순서로 자동 실행했을 때는 재현되지 않았다(5번 뒤에도 "진행 중" 열에 있었음). 직접 본 환경의 카드 수 · 이전 데이터 · 화면 버전은 확인 안 함.

### 기대 결과
- F5 뒤에도 카드가 "진행 중" 열에 있다.
- 근거: R-002, R-007, D-025 ("다시 열기"는 새로고침을 포함하고, 이때도 카드와 상태가 남아 있어야 한다)

### 실제 결과
- F5 뒤 카드가 "할 일" 열로 돌아가 있다.

### 증거
**직접 본 환경 (차이가 난 쪽)**
- 캡처 1 (F5 전, "진행 중" 열): 첨부 필요
- 캡처 2 (F5 후, "할 일" 열): 첨부 필요
- Network 탭의 PATCH · GET 값: 확인 안 함 (직접 본 환경에서 수집하지 못함)

**자동 실행 값 (2026-10-21, 검수자가 같은 순서로 자동 조작하며 Network 요청 · 응답을 기록. 사람이 F12 로 본 것이 아님)**
- 준비 `POST /api/tasks`: 보낸 값 `{"title":"장보기","description":""}` → 201, 돌아온 값 `{"id":4,...,"status":"TODO",...}`
- 상태 변경 `PATCH /api/tasks/4/status`: 보낸 값 `{"status":"IN_PROGRESS"}` → 200, 돌아온 값 `{"id":4,"title":"장보기","description":"","status":"IN_PROGRESS",...}`
- F5 전 화면: "진행 중" 열에 "장보기"
- F5 뒤 `GET /api/tasks` (같은 요청이 2번 나감): 둘 다 200, 돌아온 값 `[{"id":4,"title":"장보기",...,"status":"IN_PROGRESS",...}]`
- F5 뒤 화면: "진행 중" 열에 "장보기" (스크린샷으로도 확인)
- 이 자동 실행에서는 직접 본 결과("할 일" 열로 돌아감)가 재현되지 않았다. 두 환경의 차이(카드 수 · 이전 데이터 · 화면 버전)는 확인 안 함

## BUG-2. API 가 꺼진 채 저장하면 안내 문구가 문서와 다르다

### 재현 순서
1. API 와 화면을 켜고 http://localhost:5173 을 연다. 보드가 보이는지 확인한다.
2. API 서버를 띄운 터미널에서 Ctrl+C 로 API 를 끈다. 브라우저에서 http://127.0.0.1:8000/tasks 가 열리지 않는 것을 확인한다.
3. 화면은 새로고침하지 않은 채, 위쪽 입력 영역의 제목 칸에 "API꺼짐" 을 입력한다.
4. "저장" 을 누른다.
5. 입력 영역에 보이는 안내 문구를 확인한다. (캡처)
6. 시험이 끝나면 API 를 다시 켠다.

### 기대 결과
- 입력 영역 바로 아래에 "서버에 연결할 수 없습니다. API 가 실행 중인지 확인하세요." 가 보인다. 입력한 제목은 입력칸에 남고 카드는 생기지 않는다.
- 근거: D-005, D-021, D-027

### 실제 결과
- 입력 영역 안에 "저장하지 못했습니다. 다시 시도하세요." 가 보인다. 제목 · 설명은 입력칸에 남고 카드는 생기지 않는다.

### 증거
**자동 실행 값 (2026-10-21, API 가 꺼진 것을 확인한 뒤 기록)**
- 화면(스크린샷으로 확인): 입력 영역 바로 아래에 붉은 글씨 "저장하지 못했습니다. 다시 시도하세요." 가 보임. 입력칸에 "API꺼짐" 이 남아 있고 카드는 생기지 않음(보드의 카드 1장 그대로)
- Network: `POST /api/tasks`, 보낸 값 `{"title":"API꺼짐","description":""}` → 응답 상태 502, 응답 본문 없음 (브라우저는 이 요청을 `net::ERR_ABORTED` 로 기록)
- 같은 때 화면 서버(5173)에 `/api/tasks` 를 직접 요청: 502, 본문 없음

**직접 본 환경**
- 캡처: 첨부 필요
- Network 탭의 POST 응답: 확인 안 함

## BUG-3. API 가 꺼진 채 상태를 바꾸면 안내 문구가 문서와 다르다

### 재현 순서
1. API 와 화면을 켜고 http://localhost:5173 을 연다. "할 일" 열에 카드가 하나 이상 있게 한다.
2. API 서버를 띄운 터미널에서 Ctrl+C 로 API 를 끈다. http://127.0.0.1:8000/tasks 가 열리지 않는 것을 확인한다.
3. 화면은 새로고침하지 않은 채, "할 일" 열 카드의 상태 드롭다운에서 "진행 중" 을 고른다.
4. 카드가 어느 열에 있는지, 카드 안에 보이는 안내 문구가 무엇인지 확인한다. (캡처)
5. 시험이 끝나면 API 를 다시 켠다.

### 기대 결과
- 해당 카드 바로 아래에 "서버에 연결할 수 없습니다. API 가 실행 중인지 확인하세요." 가 보인다. 카드는 원래 열에 그대로 있다.
- 근거: D-005, D-027

### 실제 결과
- 해당 카드 안에 "저장하지 못했습니다. 다시 시도하세요." 가 보인다. 카드는 "할 일" 열에 그대로이고 선택칸도 "할 일" 이다. 입력 영역에도 앞선 실패 안내가 함께 남아 있다.

### 증거
**자동 실행 값 (2026-10-21, API 가 꺼진 것을 확인한 뒤 기록)**
- 화면: 해당 카드 안에 "저장하지 못했습니다. 다시 시도하세요." 가 보임. 카드는 "할 일" 열에 그대로이고 선택칸도 "할 일"
- Network: `PATCH /api/tasks/4/status`, 보낸 값 `{"status":"IN_PROGRESS"}` → 응답 상태 502, 응답 본문 없음 (브라우저는 이 요청을 `net::ERR_ABORTED` 로 기록)

**직접 본 환경**
- 캡처: 첨부 필요
- Network 탭의 PATCH 응답: 확인 안 함
